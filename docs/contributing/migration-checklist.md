# Migration checklist

The goal: every library that lls, sge and ssg port is generated by Baltic Porter from its upstream
sources, in the consumer's own build, from published engine artifacts. This page is the one list
of what is generated today and what is not. It is updated in the same commit that changes a
module's state; a module's residue and open defects are tracked in the consumer's own tracker.

A module is **generated** when all of the following hold:

1. its main sources are produced at build time from the upstream submodule by the consumer's own
   policy, against the published engine (no sibling checkout of anything);
2. every hand-written file that replaces or completes generated output is counted here and
   covenanted in the consumer;
3. the upstream's own tests run on the port (a refused test family is named, not dropped);
4. the consumer's platforms are all green.

States used below: **generated** (all four hold; the residue is stated), **generated, partial**
(1 holds, 2 to 4 have named gaps), **policy present** (a policy exists but nothing is wired to it),
**hand-written** (no generation at all), **not a port** (original code, listed so that nothing hides).

## ssg: non-Java libraries

The engine has TypeScript/JavaScript and Dart frontends. In ssg every non-Java module still ships
its hand-written reference tree; the generator is called for five of them but with no translated
bodies (it copies the reference verbatim) and with the exported syntax trees read from a sibling
engine checkout, so today these are hand-written in effect. The translated-body shares below were
measured in the engine, not applied in ssg.

## Engine work the checklist depends on

- The non-Java body builders that name katex, terser, dart-sass and mermaid still live in the
  engine's `frontend-ts`; they move to ssg with the wiring above.
- The exported syntax trees for the non-Java libraries are engine test fixtures today; ssg needs to
  export them from its own submodules (Node for TypeScript, the Dart SDK for sass).
