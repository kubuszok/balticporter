# Generated code in a Baltic Porter consumer

## How it is wired

- `project/plugins.sbt` pins `balticporter-corpus` (and `-frontend-ts`) at `<40-hex engine commit>-SNAPSHOT`,
  resolved from Maven Central's snapshot repository. There is **no engine checkout**: the jar carries the
  support files the port's policy injects and they are unpacked under `target/balticporter-engine/`.
- `project/BalticPorterGen.scala` runs the port inside the sbt JVM as a source generator. Input: the upstream
  Java sources in a git submodule under `original-src/`. Output: `target/balticporter-<module>/src_managed/`
  (`main/scala` shared, `<jvm|js|native>/scala` per platform row, `main/resources`).
- The output is reused while `target/balticporter-<module>/.generated-marker` matches the engine pin, the
  upstream commit, the generator source and the JDK major. Force a regeneration by deleting that marker.
- Run only the generation with `sbt --client generatePort`.
- The sbt server must run on the JDK the repository states (sge: 25). The generated code differs by JDK
  major (a member gets `override` only where that JDK's supertype declares it). On macOS
  `/usr/libexec/java_home -v 25` may silently answer an older JDK — check `java -version`.

## Rules

1. **Never edit a generated file**, and never patch hand-written code, a test or a build setting to fit a
   generated defect. The next generation overwrites the first, and the second hides a translation bug
   from every other consumer. A hook blocks edits under `src_managed/`.
2. A wrong generated member is fixed where it is decided, in this order:
   - the port's **policy** (a rename, a dropped or injected type, a method body rule) — in Baltic Porter's
     corpus module for this library;
   - the **engine** (a translation rule every library would want);
   - an **injected hand-written file** shipped by the policy, when no mechanical translation exists —
     look at what the previous hand port did at that exact site first.
3. No test is skipped, ignored, deleted or rewritten to pass; no warning filter, exclusion or baseline is
   widened to get green. If a generated API differs from what a test expects, decide which one matches
   the upstream Java behaviour — Java wins for behaviour, the previous hand port wins for API spelling.
4. Platform limits (no threads on Scala.js, no client-memory vertex arrays in WebGL, no reflection on
   Scala.js/Native) are answered at the smallest site the upstream project itself answered them
   (libGDX's GWT backend emulation is the reference), as a per-platform source row — never by moving
   shared tests off a platform.

## Tracing an error back to its cause

1. Read the first error, not the count: one typer error hides every later phase's errors.
2. Find the generated member. Each generated declaration carries a `/* porter: … */` note saying which
   rule produced it and why (`reason=universal|configured|library-rule`, `phase=…`, `key=…`).
3. Reproduce it in Baltic Porter with the smallest Java input as a spec in the engine or corpus test
   suite, fix it there, and check every consumer still generates and compiles (`just consumers-check`).
4. Publish and repin (below). Only then touch the consumer, and only its pin.

## Bumping the engine pin

1. Push the engine change to Baltic Porter's `master` **once**. Each push starts a snapshot release, and a
   second push within minutes CANCELS the first one's release — that commit is then never published.
2. Wait for the release workflow to finish, then prove the artifact exists:
   `curl -s -o /dev/null -w '%{http_code}' https://central.sonatype.com/repository/maven-snapshots/com/kubuszok/balticporter-corpus_3/<sha>-SNAPSHOT/balticporter-corpus_3-<sha>-SNAPSHOT.pom` → `200`.
3. Replace the hash on BOTH pin lines of `project/plugins.sbt`, regenerate, run the full local gate
   (`sbt --client verifyLocal`: JVM, Scala.js and Scala Native tests), then push once.
4. For a local iteration before publishing: commit in Baltic Porter (the version is the commit hash),
   `sbt --client publishLocal` there, pin that hash locally. Never push a pin that is not on Central.
